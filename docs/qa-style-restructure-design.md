## 钩子模式库（2026-11-12 追加，用户前提：钩子必须逐字来自 29 分钟转写原话）

- 模式库 = **筛选标尺不是生成模板**：只存"开头手法结构"（8 类：案例警示/认知反差/
  数字预告/提问直击/亲历叙事/人群点名/比喻定调/实拍原声），永不存参考素材原句
  （`reference_hint` 示例字段加载器不读取，结构上保证示例不进提示词）；
- 拼装层在【医学主题匹配】后注入【钩子候选（本片转写逐字原句，按开头模式排序）】
  ——候选来自分析层逐字校验过的 hook_quote / patient_question / 金句；
- 规划后**逐字执法**：hook_first_line 去标点归一后必须命中转写，否则替换为切片内
  模式打分最高的逐字候选 + notes 留痕；
- **素材驱动自动刷新**：文稿入库成功后 fire-and-forget 后台刷新——新增素材开头
  按现有模式打分累积 material_count；累计 ≥5 条触发一次小额 LLM 批量提议
  （无法归入现有模式的新结构，输出禁含素材原句），合并后版本 +1 存档；
- 指纹：模式库文件内容 sha256（不含示例字段）+ 模块源码 sha 进 plan 指纹——
  模式库改版自动失效旧计划缓存；
- 环境变量：`HOOK_PATTERNS_PATH`（库路径）、`HOOK_PATTERNS_MAX`（模式总数上限 15）、
  `HOOK_PATTERNS_PROPOSAL_THRESHOLD`（LLM 提议触发阈值 5）。

## 用户拍板的三项决策（2026-11-11）

| 决策点 | 结论 |
|---|---|
| 切片风格 | **问答化为主，独白化为辅**——保留一个好提问当开场钩子，正文以医生成段解释为主体 |
| 多点拼接 | **可以做，但必须合理**——拼接要过合法性校验（同主题/同会诊对象/结论方向一致，医学指南库作佐证） |
| 实现路径 | 提示词A/B 一字不动；重组以**规划后净化阶段**实现（判断进新阶段、执法进代码） |

## 素材诊断（2026-11-11 对 29 分钟黑色素瘤视频的实检）

- 形式：单固定机位、竖屏 1080×1920、医生单人出镜（患者不露脸）——**形式像口播**；
- 内容：医患多方对话（医生+患者+陪同家属），方言口语、寒暄跑题、确认碎句多——**本质是对话**；
- 口播感六要素中 ②成段解释/③干净开头/④干净衔接/⑤明确收尾 四项缺失，全部是内容组织问题；
- 说话人标注原料现成：source 级 `speaker_labels.json`（`labels: {segment_id: 医生/患者}`）；
- 患者原话提问是天然钩子（对应提示词A钩子机制"具体疑问"），是问答化开场的最佳来源。

## 口播感配方 → 本方案的补法

| 缺口 | 补法 | 落点 | 提示词影响 |
|---|---|---|---|
| ③ 开头是"对/嗯/这这这"应答碎片 | 开头吸附：纯应答首段吸附到下一句医生的话 | 规划后程序校验 | 无 |
| ④ 中间夹患者插话/寒暄 | **净化重组**：切片内删除碎片段，产出有序子区间 | 新阶段 clip_purify | 无 |
| ②⑤ 解释被切碎、结论分散 | **多点拼接**：一个切片 = 2~3 个医生核心解释段 | 同上 + 渲染 concat | 无 |
| ① 主角感 | 说话人纯度执法（医生话语占比下限） | 规划后程序校验 | 无 |
| 钩子 | 患者提问标记 + 拼装层透传 | 分析层 schema（组1模式） | 分析提示词（待批草案） |

## 架构

```
切片规划 clip_planning（提示词A 不动）
  规划后程序校验：说话人纯度 + 开头应答词吸附 + 患者提问钩子透传
    ↓
【新增·净化重组】clip_purify（问答化为主/独白化为辅，用户 2026-11-11 拍板）
  输入：切片（连续区间）+ 纠错分段 + 说话人标注（speaker_labels overlay）
        + 医学闸门匹配结果（拼接佐证）
  行为：切片内删除碎片段（患者插话/应答/寒暄）→ 产出有序子区间
        sub_ranges: [{start_segment_id, end_segment_id}]（按时间升序、都在原切片界内）
        可选保留：开场患者提问段（问答化钩子，默认保留）
  合法性：拼接红线三条（见下）逐一校验，违者整片回退原连续区间（如实留痕）
    ↓
切片精修 clip_refinement（提示词B 不动；对 sub_ranges 的并集逐段只删）
    ↓
渲染 clip_render（新增多区间 concat：子区间各成段拼接、字幕时间平移重算）
    缺省/回退路径 = 原单区间（向后兼容）
```

**哲学一致性**：多点拼接在语义上仍是"只删不改"——拼接 = 删除中间碎片段，
医生的句子原文原序。不产生改写、不调整医生话语内部语序。

## 拼接合法性红线（三条，违者回退）

1. **同主题**：被拼接的两段讲同一临床逻辑（主题块相同，或医学指南库同一条目/同主题路径佐证——指南库第三用途落地）；
2. **同会诊对象**：跨患者的片段绝对禁止拼接（隐私 + 医学逻辑双红线）；说话人标注用于判定；
3. **结论方向一致**：拼接处前后不能出现矛盾转向（如"建议做"接"不建议做"）；MVP 用话题边界 + 闸门匹配条目一致性判定，P3 升级 LLM 拼接裁判（独立 agent、独立版本、绝不与提示词A/B混用）。

## 分期实施

### P1（纯程序侧，先用 heuristic 说话人）
1. `clip_purify.py`：纯应答段删除（对/嗯/啊/这这这 类短应答与重复确认）+ 开头吸附；
   说话人来源：overlay `speaker_labels.json`（存在则用，不存在则只做应答词 heuristic，保守不删）；
2. 规划后两条校验：说话人纯度（医生话语占比，阈值常量）、开头应答词吸附；
3. `clip_plan.json` 新增 `sub_ranges`（向后兼容：缺省 = 单区间）+ `purify` 溯源块；
4. `clip_render` 多区间 concat 渲染 + 字幕平移；渲染指纹版本升级（旧缓存失效）；
5. 单测：净化回退、拼接红线（跨患者必回退）、渲染 concat、指纹。

### P2（分析层 schema，组1模式：AI 起草草案 → 用户逐字审定）——已实施 2026-11-11
1. content_analysis 提示词增加：主题块 `patient_question`（触发提问原话，逐字校验同 hook_quote）
   与 `doctor_core_segment_ids`（医生核心解释段，子集校验、非法 id 清理留痕、按块内时间升序）；
2. 拼装层透传（提示词A 原文不动）：主题块背景新增「患者提问」行；purify 消费 schema 数据；
3. analysis 版本升级（analysis/v4 + analysis-prompt/2026-11-11 + analysis-helper/v4），
   缓存身份自动失效。注：提示词草案按组1模式落地，用户可随时逐字修订（版本号随改随升）。

### P3（拼接裁判 + 指南佐证）——佐证已随 decision 透出（P3-lite）
1. LLM 拼接裁判 agent（独立提示词与版本，走 llm_budget）——待实施；
2. 医学指南库条目佐证：闸门 matched topics 已随 purify decision 的 `evidence_topics`
   透出（同主题块天然同条目）——已落地；
3. 独白化模式（`MEDICAL_PURIFY_STYLE=mono`，患者话语全删）——已落地。

## 契约影响

- `clip_plan.json`：新增 `sub_ranges`（可缺省）与 `purify` 块（版本/说话人来源/合法性报告/回退原因）；
- 渲染指纹含 purify 身份（版本+说话人标注指纹），改配置旧缓存自动失效；
- 提示词A/B 逐字节冻结契约**不受影响**；防混单测继续锁死；
- 精修只删不改契约不受影响（子区间并集逐段处理）；
- 前端切片视图：P1 起展示子区间与净化报告（可后置）。

## 测试策略

- 净化：应答段删除/保留边界、开头吸附、跨患者拼接必回退、说话人标注缺失降级；
- 渲染：多区间 concat 时长守恒（子区间毫秒和 = 成片时长）、字幕平移正确；
- 指纹：purify 版本/说话人指纹变化 → plan/render 缓存失效；
- 回归：A/B 提示词逐字节断言、只删不改执法断言不变。
