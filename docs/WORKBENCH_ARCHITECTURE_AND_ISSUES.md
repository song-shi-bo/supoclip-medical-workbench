> 用途：对外/对内介绍工作台**现有功能架构**，并如实说明**当前问题**与**未来方向**。
> 配套文档：技术细节见 `docs/ARCHITECTURE.md`；改进项与优先级见 `docs/WORKBENCH_IMPROVEMENT_ROADMAP.md`。
> 数据口径：截至 2026-10-12，问题条目均来自本日实测（含真实任务、真实失败、真实日志）。

## 〇、一页纸总览（可直接当第一页）

**一句话定位**：一个面向**医疗科普**的「长视频 → 短视频切片」工作台，把**医生的口播长视频**按固化规则自动切成多条可发布成片，并让每条成片成为**可持续编辑的资产**（改封面/标题/字幕/时间线都不影响其它成片）。

**六层能力（今天已跑通）**
```
① 素材层    分片上传 · 源片单副本化（硬链接零占用）· 陈旧副本回收
② 理解层    ASR + 医学热词表 → LLM 医学纠错（四条红线）→ 结构化转写（只读可信）
③ 规划层    成员裁定版策划提示词 → 硬校验（时长/重叠/证据/条数）→ 主题·钩子·标题·关键词
④ 生成层    video-brain 固定流程：切片渲染 · 字幕 · 封面 · 0.8s 片头 · QC
⑤ 编辑层    剪映式画面变换/裁剪（预览=导出）· 封面资产化与撤销 · 四类局部任务
⑥ 治理层    项目台账（稳定 clip_id·一卡一片）· 规则清单与任务快照 · 规则中心 · Copilot
```

**三个最有说服力的卖点**
1. **可复现**：每次任务冻结一份规则快照（workflow vX + 各 skill 版本），规则升级只影响新任务、旧成片可回查历史规则；
2. **可持续编辑**：重制封面**不重跑自动剪辑、不新增卡片**，且只重拼 0.8s 片头——实测正片 581 帧逐帧不变、时长 23.2762s 不变；
3. **合规优先**：纠错四红线（不改诊断/药名/剂量/否定词）、封面上不上身份贴纸需明确确认、缺依赖一律显式报错不静默降级。

## 一、现有功能架构

### 1.1 分层架构（讲解用）

| 层 | 组成 | 用户可见形态 |
|---|---|---|
| **入口/身份** | DSH 公网入口（Caddy → socket）、登录会话、API Key | 打开工作台、程序化调用 |
| **素材层** | 分片上传/组装、**源片单副本化**、`source_gc` 回收 | 「上传视频」、项目源片 |
| **理解层** | ASR（**医学热词表**，改文件即生效）→ LLM 纠错（**四条红线** + 术语表权威）→ `uncertain` 标记 | 转写面板（只读）、热词表 |
| **规划层** | **成员裁定版提示词**（逐字固化）+ 硬校验（25–45s、重叠 ≤20%、证据重叠、条数规则）+ `planning_meta` | 「开始自动剪辑」后的切片方案 |
| **生成层** | video-brain 固定流程：规划 → 渲染切片 → 字幕 → 封面 → 0.8s 片头 → QC | 成片卡片、字幕、封面 |
| **编辑层** | 画面变换/裁剪（**非破坏参数**、`viewerZoom` 与 clip transform 分离）、时间线 EDL、四类局部任务 | 播放器工具栏、卡片菜单、助手指令 |
| **资产治理层** | **项目台账 `clips.json`**：稳定 `clip_id`、`render_task_id` 冻结、`cover_asset_id`/revision/history、`task_history` | 左侧成片卡片（一卡一片、版本徽标） |
| **规则治理层** | **规则清单** + **任务级规则快照** + 四级优先级 + 规则中心（查看/启停/按最新规则重生成） | 顶栏「当前使用 vX」、规则中心面板 |
| **助手层** | Copilot 绑定**选中成片**、白名单动作 + 类型化任务（REGENERATE_COVER / UPDATE_TITLE / UPDATE_SUBTITLE_STYLE / UPDATE_TIMELINE）、confirm 确认流 | 左侧剪辑助手 |
| **合规层** | 纠错红线、规划红线、导出标识与免责声明（待落地）、审核留痕 | 合规清单 |

### 1.2 一次完整旅程（讲解主线）

1. **上传** 医生长视频 → 源片落盘一份，后续全部硬链接引用；
2. **转写** 医学热词注入提升专名命中 → LLM 纠错按四条红线只改错别字 → 人工可核（当前只读展示）；
3. **开始自动剪辑** → 冻结**规则快照** → 规划器按成员规则出若干切片（主题/钩子/标题/核心原话/关键词）；
4. **生成** 每条切片渲染成 9:16 成片（字幕烧录、封面片头 0.8s、QC），登记为**稳定 clip_id**；
5. **编辑** 选中一条成片：改封面（风格/字数）、改标题、改字幕样式、删时间区间——**只动这一条的资产或时间线**；
6. **导出/留痕** 默认变换直下原片、非默认变换按参数重渲；每次修改留 revision 与任务历史，可撤销、可回查规则版本。

### 1.3 关键数据与契约（用来回答"凭什么是可复现"）

| 契约 | 内容 |
|---|---|
| 项目台账 | `tasks/projects/{project_id}/clips.json`（卡片唯一事实源） |
| 任务产物 | `tasks/output/<task>/<clip>/{clip_final.mp4, cover.jpg, cover_layout.json, cover_revisions/…}` |
| 规则快照 | `tasks/output/<task>/workflow_snapshot.json`（版本 + 各 skill checksum + 生效规则 + 来源） |
| 源片 | 唯一物理副本 + 全链路硬链接（**源片只读**） |
| 变换 | 归一化 `scale/positionX/positionY/crop`；后端与前端共用同一套数学（10 组对照向量守护） |

## 二、问题总结（如实）

> 每条格式：**现象 → 根因 → 影响**。按类别分组，★ 为对外汇报时最该提的。

### A. 架构性问题

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| A1 ★ | 同仓库存在**两套剪辑链**（legacy SupoClip 与 Studio/video-brain） | 历史演进：legacy 服务于早期任务页，Studio 是后加的 | 新人上手要分辨"该看哪条链"；测试与文档成本翻倍 |
| A2 ★ | 状态分散在三处：数据库 `studio_jobs` + 文件台账 `clips.json` + 任务 JSON | 逐步演进，未做单一事实源的统一 | 一致性靠约定维持；排查问题需三处对照 |
| A3 | 渲染权威有两处：`intro_duration_s` 既进规则快照又在 video-brain 配置 | 片头时长由 video-brain 实现，工作台只记录 | 两边不一致时以 video-brain 为准，容易误解 |
| A4 | 三个能力只有"占位"：字幕合成、说话人分离、金句提取 adapter 均未实现 | video-brain 无跨服务端点 / 无该能力 | 规则清单里有条目但**调用即显式失败**（好在不静默） |
| A5 | 局部修改与完整重渲边界仍在收敛：`UPDATE_TIMELINE` 的重渲是显式开关；产物回传仍走执行器导出通道 | 本轮刻意保守，避免测试误建真实任务 | 用户预期"删区间就重渲"与实际行为有差 |
| A6 ★ | 手工启动的 PostgreSQL **不能随容器自愈** | PG 由人工 `pg_ctl` 启动，非 supervisor 托管 | 今日实测：容器重启后 PG 掉线 + 陈旧锁文件 → 后端/worker 起不来，需人工恢复 |

### B. 体验性问题

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| B1 ★ | 窄屏（1366 及以下）裁剪模式**画面过小**（约 141×79） | 浮层预留空间挤压画布 | 笔记本上精细调构图困难（有折叠补偿但不理想） |
| B2 ★ | 助手 LLM 调用 **42–45 秒临界超时**，超时即降级规则引擎 | 单次 LLM 调用超时上限 45s，无重试 | 体验断崖：同一句话有时"聪明"有时"模板化" |
| B3 | 无**执行前方案预览与消耗预估** | 未实现 | 用户点 confirm 前不知道要花多少时间/额度 |
| B4 | 撤销能力只覆盖封面 | 未做统一撤销栈 | 改标题/字幕/时间线后无法一键回退 |
| B5 ★ | 转写只读后**没有人工修订入口** | 为满足"不可修改"需求，把审核端点短路成 410 | 纠错仍出错时只能等改词表/提示词，缺临时救济 |
| B6 | 卡片无批量/筛选/搜索；「删除」仅视图移除 | 未实现 | 成片一多就难管理 |
| B7 | 任务详情缺"规则版本 + 产物清单"统一视图 | 未实现（数据已具备） | 排查与验收要靠 API/文件 |

### C. 质量与内容问题

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| C1 ★ | 时长**硬卡 25–45s**，会误杀 50s 的原理科普 | 校验器按统一区间；调研显示各主题最佳时长不同 | 好内容被丢弃或被迫压短 |
| C2 | 封面"手表/手势完整可见"等要求靠**比例窗启发式** | 无检测模型 | 达不到要求时需人工指定帧 |
| C3 ★ | 第三版抠像封面**缺 u2net 权重就不可用** | 容器无外网下载 176MB 权重 | 该风格当前只能报错（第二版可用） |
| C4 | 标题 grounding 与禁词校验是**字面级** | 禁词表是类别名（疗效承诺/绝对化…） | 语义级违规仍可能漏过 |
| C5 | 早期默认封面风格曾指向 legacy，导致"每版封面长得一样" | 风格参数未贯通（已修） | 已修复，但说明**参数贯通类缺陷很隐蔽** |

### D. 合规性问题（优先级最高）

| # | 现象 | 影响 |
|---|---|---|
| D1 ★ | **AI 内容标识未实现**（法规 2025-09-01 已施行，医疗科普被点名） | 导出物缺显式标识 + 元数据隐式标识 → 合规风险 |
| D2 ★ | **免责声明未固化**到成片/发布文案 | 医疗内容缺固定声明 |
| D3 ★ | **审核留痕与状态机未落地**（谁在何时批准哪一版） | 平台抽查资质与内容时缺证据链 |
| D4 | 素材授权边界未在系统内提示 | 第三方商用素材**禁用于医疗类宣传**，误用有风险 |

### E. 运维与成本问题

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| E1 ★ | 磁盘曾在 92–96% 时触发**建任务失败**（`E_DISK_SPACE`，仅剩 197MB < 500MB 门限） | 早期复渲染无条件复制 3GB 源片 | 任务无声失败（现已改硬链接 + 错误码透出） |
| E2 | `backend/temp` 长期增长（曾达 12G） | 任务工作区/上传/分片长期留存 | 需定期 GC，否则反复触碰门限 |
| E3 | 历史副本仍有约 17G 可回收（多份引用副本未重挂） | 单副本化只防新增，未迁移存量 | 磁盘压力持续 |
| E4 | LLM 配额（并发 1、每日配额）与降级策略不透明 | 未做可视化 | 用户不知为何突然降级 |
| E5 ★ | 缺**发布与数据回流**闭环 | 未实现（国内平台发布需企业资质） | 目前只能"产出成片"，无法闭环验证效果 |

## 三、未来方向（三句话 + 三档）

**三句话**
1. 短期把**合规做成功能**（AI 标识 / 免责声明 / 审核留痕）——这是法规要求，也是差异化卖点；
2. 中期把**规则与资产治理做深**（规则变更历史、统一撤销、批量与筛选、任务详情视图）；
3. 长期补 **发布与数据回流闭环**（企业资质 → 扫码半自动发布 → 表现数据回灌规则）——竞品普遍没做好，是护城河机会。

| 档 | 内容 |
|---|---|
| **一个月内**（纯自研零资质） | 分主题时长校验 · 钩子负例与标题模板库 · **AI 标识+免责声明+导出前合规自检** · 术语表一键加入与审核闭环恢复 · 响度统一与降噪 · 智能剪口播 · 规则中心收尾 · 助手方案预览与统一撤销 |
| **一季度**（例行手续/中等工程） | 扫码发布链路 · 视频互动数据 API → 回流看板 · 字幕/花字样式库 · 多尺寸批量导出 · 医生/科室与品牌资产库 · 审核状态机+帧级批注+权限 · 横转竖主体追踪 |
| **需资质/慎入** | 全自动代发布（白名单）· 投流报白 · **数字人与声音克隆（不建议）** · 补帧/超分 |

## 五、汇报时可能被追问的问题（预备答案）

| 追问 | 回答要点 |
|---|---|
| 和剪映/OpusClip 比，你们强在哪？ | 医疗合规内建（纠错红线、术语权威、AI 标识、审核留痕）+ **规则快照可复现** + 成片级资产化编辑；不追求泛化剪辑能力 |
| 为什么不做数字人？ | 监管严打 AI 仿冒医生（已封 1.1 万账号），医生形象属敏感个人信息，**主动不做** |
| 15 秒还是 30 秒？ | 有实测依据：前 5 秒留存与观看深度相关 0.83；15s 偏短、25–45s 为知识口播主力区，且各主题最佳区间不同 |
| 换风格/改规则要重跑吗？ | 不需要：任务冻结快照，规则更新只影响新任务；旧成片可查历史规则版本，也可「按最新规则重新生成」（生成新 revision、不覆盖旧成果） |
| 稳定性怎么保证？ | supervisor 托管子进程 + 显式错误码 + 磁盘门限 + 源片单副本化；但**PostgreSQL 仍需改为托管**（当前短板，已列入计划） |
